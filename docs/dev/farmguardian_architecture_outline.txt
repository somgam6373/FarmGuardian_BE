팜가디언 백엔드 아키텍처 요약 (2026-10-04, 개정 2026-10-11 PRD 반영)
상세: farmguardian_architecture.md / farmguardian_judge_rules.md / PRD 수정 제안: farmguardian_prd_feedback.md

[Stack]
 FastAPI(동기) · PostgreSQL+PostGIS(5179) · SQLAlchemy 2 + Alembic · 카카오 로그인 → 자체 JWT
 프론트는 별도 담당 (폴리곤 SVG 렌더링도 프론트, 지도 없음)
 지원 작물: 감자 · 배추 · 토마토 (모두 일년생)

[Module]  폴더 = 담당
 팀원: 팜맵·밭·구역 만들기 + 외부 연동
       integrations(juso·pnu·farmmap·GML 파서·kma) / fields(밭 생성·목록·삭제, 분할 split.py 순수, 구역 생성)
 팀장: 나머지 — judge(rules.py는 순수, DB·HTTP 없음) / records / auth / ingest(PSIS·NCPMS·매개충 시드)
       / pests / zones(상세·속성 수정) / core(설정·DB·JWT·에러·today_kst) / seed_demo

[Tabs]  프론트 탭 4개 (첫 사용은 온보딩을 마쳐야 탭 사용)
 홈 = 내 밭·구역 상태 / 병해충 = 구역 → 병해충 → 약제 → 판정 → 기록
 조회수정 = 이력·구역·밭 / 프로필 = 출처·면책 안내, 로그아웃, 회원 탈퇴

[Onboarding = Setup]  GET /me {onboarded} false면 아래 1~5, 끝나면 POST /me/onboarding
                     (구역 없음·「누락 없음」 안 된 구역 → 422 ONBOARDING_INCOMPLETE, 멱등)
 1. 로그인          POST /auth/kakao → JWT
 2. 주소 검색        GET /addresses/search (juso → PNU)
                    GET /parcels?pnu → 그 지번과 겹치는 팜맵 필지 전체 (이웃 지번 필지 포함)
                    · 필지마다 지번·논/밭/과수/시설·촬영년도, 조회 지번과 같은지(matches_query),
                      이미 다른 밭이 쓰는지(used_by_field_id)
 3. 밭 만들기        POST /fields {name, 필지 id[]}
                    · 필지 도형 병렬 조회(동시 8개 이하), 등록 시 1회 → field_parcel.geom
                    · 밭 도형 = 필지 합집합 (떨어진 필지도 한 밭 가능)
                    · 필지는 사용자당 한 밭에만 (중복 시 409 PARCEL_ALREADY_USED)
 4. 구역 나누기      POST /fields/{id}/split-preview {direction, ratios} → 조각 도형 (저장 안 함)
                    POST /fields/{id}/zones {direction, ratios, zones: [{name, crop_id, planted_at?}]}
                    · direction = 밭의 긴 변 기준 crosswise(토막) | lengthwise(띠)
                    · ratios: 균등 [1,1,1] / 비율 [6,4] (PRD 드래그 수정 대체) / [1] = 밭 전체
                    · 서버가 다시 계산 (같은 입력 = 같은 도형), 클라이언트 도형은 받지 않음
                    · 이미 구역 있음 → 409 FIELD_ALREADY_SPLIT (재분할 P1, 지금은 밭 삭제 후 다시)
                    · 면적 = ST_Area(zone.geom) (팜맵 기준 참고값)
 5. 과거 이력        POST /zones/{id}/sprays (source=manual)
                    PATCH /zones/{id} {history_confirmed: true}  ← 「누락 없음」

[Judge]
 1. 구역 선택        (프론트)
 2. 병해충 지목      GET /crops/{id}/symptom-parts → GET /pests/candidates
                    GET /pests?crop_id&q  ← 도감 목록·이름 검색 (NCPMS에 없는 PSIS 병해충도)
                    · PestCard: 사진·설명·발생시기(참고, 출처·기준 시점) · 바이러스면 매개충 목록
                    · 매개충을 고르면 일반 병해충처럼 판정 (바이러스 치료로 설명 금지)
                    · 선택 안 하고 진행 가능
 3. 약제 목록        GET /pesticides?crop_id&pest_id  ← DB(PSIS 적재분), 요청 시 PSIS 호출 없음
 4. 약제 선택        POST /zones/{id}/judgments → judge()
      ① 등록   작물×병해충×상표 행 있나 (병해충 미지정 → 확인 필요, 작물 미등록 → 불가)
      ② 시기   오늘 + PHI = 수확 가능일 표시 (불가 없음)
      ③ 횟수   같은 품목명 이력 합산, 정식일 이후, 남은 횟수 / 이번 사용 후, 소진 시 불가
               정식일 없음 · 누락 확인 전 → 확인 필요
      ④ 작용기작  최근 3건 중 같은 계열 2건 이상 → 주의 (누락 확인 전 → 확인 필요)
 5. 결과            가능/주의/불가/확인 필요 (불가 > 확인 필요 > 주의 > 가능)
                    + 체크 4개 사유·근거 원문·데이터 조회일 (근거는 항상 있음)
                    + 불가·주의면 다른 작용기작 대안 (병해충 지목 시만)
                    + 병해충 지목했고 대안 0건이면 농업기술센터 문의
 6. 날씨            GET /zones/{id}/weather → 시간대별 강수(PTY·PCP·POP) + 발표 시각
                    · 구역 중심점 → 기상청 격자, 저장 없음, 실패해도 판정 동작

[Record]
 1. 「살포 기록 저장」 POST /zones/{id}/sprays {request_id, ...} (source=app, 기본 오늘 KST, 미래 거부)
                    · 같은 request_id 재시도 → 기존 기록 반환 (한 번만 반영)
                    · 같은 구역·약제·날짜 있음 → 409 DUPLICATE_SPRAY
                      → 기존 기록 확인 / 별도 살포로 저장(allow_duplicate) / 돌아가기
 2. 취소             DELETE /zones/{id}/sprays/{sid}

[Browse]
 1. 내 밭            GET /fields → 밭별 구역 요약 (last_spray + last_judgment, 기록 없음 표시)
 2. 구역 상세        GET /zones/{id} → 편중도(작기 전체 건수, 정식일 없으면 전체) + 최근 판정 5건
                    GET /zones/{id}/sprays (이력, 이번 작기 여부는 프론트가 planted_at으로 구분)

[Edit]
 1. 구역 수정        PATCH /zones/{id} {name?, crop_id?, planted_at?, history_confirmed?}
                    · 작물 변경 → 정식일 새 값 또는 비움 (비우면 ③ 확인 필요)
                    · 정식일이 바뀌면 「누락 없음」 해제
 2. 기록 취소        DELETE /zones/{id}/sprays/{sid}  (수정 API 없음, 취소 후 다시 입력)
 3. 밭 삭제          DELETE /fields/{id} → 구역·기록·판정 CASCADE (잘못 고른 필지, 다시 나누기)

[Profile]
 1. 로그아웃         프론트가 토큰만 지움
 2. 회원 탈퇴        DELETE /me → users CASCADE(밭·구역·기록·판정) 커밋 후 카카오 연결 끊기(어드민 키)
                    · 연결 끊기 실패해도 204 + 로그, 탈퇴 뒤 남은 JWT는 401

[Data]
 참고(적재): crop · pest · pest_info(작물별 사진·설명·발생시기) · pest_symptom · pest_vector(매개충)
            · moa · pesticide · registration
 사용자:     users(onboarded_at) · field · field_parcel(user_id, 지번, 논/밭, 촬영년도) · zone(geom, planted_at NULL,
            history_confirmed) · spray_log(request_id) · judgment

[Ingest]  수동 실행
 PSIS 목록 API(XML) → 문자열 파서(PHI·횟수, 못 읽으면 None + 원문 보관) → upsert(멱등)
   → 작물별로 응답에서 빠진 registration 행 삭제 (등록 취소 반영, pesticide는 남김)
   → 오류·0건·절반 미만으로 급감하면 전체 롤백 (확인 후 --allow-shrink)
 NCPMS 도감 → pest_info · pest_symptom (1회)
 매개충 CSV(줄마다 출처) → pest_vector
