[Module]  폴더 = 담당

[Setup]
 1. 로그인          POST /auth/kakao → JWT
 2a. 주소 검색       GET /addresses/search (juso → PNU)
                    GET /parcels?pnu → 그 지번과 겹치는 팜맵 필지 전체 (이웃 지번 필지 포함)
                    · 필지마다 지번·논/밭/과수/시설·촬영년도, 조회 지번과 같은지(matches_query),
                      이미 쓰는 필지인지(used_by_zone_id)
 2b. 직접 입력       폼 값만 (구역 이름 + 면적 또는 가로×세로)
 3. 구역 만들기      POST /zones {필지 id[] | manual, 작물, 정식일}
     (선택) 분할     POST /zones/batch {zones: [...]}  ← 필지를 묶음별로 나눠 구역 여러 개를 한 번에
                    · 구역마다 작물·정식일이 하나라서 "같은 작물·같은 정식일·같이 방제"가 구조로 지켜짐
                    · 필지는 사용자당 한 구역에만 속함 (중복 시 409 PARCEL_ALREADY_USED)
                    · 필지 도형은 구역마다 따로가 아니라 병렬 조회, 등록 시 1회만 → zone_parcel.geom
                    · 면적 = ST_Area (팜맵 기준 참고값, 수동은 입력값)
 4. 과거 이력        POST /zones/{id}/sprays (source=manual)
                    PATCH /zones/{id} {no_prior_spray: true}

[Judge]
 1. 구역 선택        (프론트)
 2. 병해충 지목      GET /crops/{id}/symptom-parts → GET /pests/candidates
 3. 약제 목록        GET /pesticides?crop_id&pest_id  ← DB(PSIS 적재분), 요청 시 PSIS 호출 없음
 4. 약제 선택        POST /zones/{id}/judgments → judge()
      ① 등록   작물×병해충×상표 행 있나
      ② 시기   오늘 + PHI = 수확 가능일 표시 (불가 없음)
      ③ 횟수   같은 품목명 이력 합산, 정식일(다년생 1/1) 이후, 최대횟수 도달 시 불가
      ④ 작용기작  최근 3건 중 같은 계열 2건 이상 → 주의
 5. 결과            가능/주의/불가/확인 필요 (불가 > 확인 필요 > 주의 > 가능)
                    + 체크 4개 사유·근거 원문·데이터 조회일
                    + 불가·주의면 다른 작용기작 대안 (병해충 지목 시만)
                    + 대안 0건이면 농업기술센터 문의

[Record]
 1. 「이 약 쓸게요」  POST /zones/{id}/sprays (source=app, 살포일 기본 오늘 KST, 미래 날짜 거부)
 2. 취소             DELETE /zones/{id}/sprays/{sid}

[Browse]
 1. 구역 목록        GET /zones (last_spray + last_judgment)
 2. 구역 상세        GET /zones/{id} → 편중도(작기 전체 건수) + 최근 판정 5건
                    GET /zones/{id}/sprays (이력)
 3. 수동 구역        폴리곤 null + 가로×세로 → 프론트가 개략 배치도

[Edit]
 1. 구역 수정        PATCH /zones/{id}
                    · 작물 변경 → planted_at 필수 (없으면 422 PLANTED_AT_REQUIRED)
                    · parcel_farmmap_ids = 필지 목록 전체 교체 (빠진 필지는 해제, 새 필지만 팜맵에서 받음)
                    · 수동 구역에 필지 나중 연결도 같은 방식
 2. 구역 분할(사후)  POST /zones/{id}/split {parts[], keep_index}
                    · 필지 구역은 파티션 필수 (합집합 = 원래 필지, 겹침·빈 부분 없음, 어기면 422)
                    · keep_index 부분이 원래 구역을 이어받음 (같은 id, 판정 기록 유지)
                    · 이력은 모든 새 구역에 복사 (나눠 가지면 횟수를 적게 세어 "가능"이 잘못 나옴)
                    · 작물 바뀐 부분도 이력 복사, ③은 정식일 창이, ④는 최근 3건이 알아서 처리
 3. 이력 수정·삭제   PATCH / DELETE /zones/{id}/sprays/{sid}
