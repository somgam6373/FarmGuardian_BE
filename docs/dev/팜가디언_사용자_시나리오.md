# 팜가디언 사용자 시나리오

- 작성일: 2026-10-28
- 용도: API 24개를 한 번씩 모두 쓰는 시연·검수용 흐름이다. 기준은 `팜가디언_API_명세.md`.
- 외부 API(팜맵·juso·기상청)와 DB는 실제로 호출해 보지 않았다. 명세 기준의 시나리오다.

## 김씨의 첫날 (배추 밭)

### A. 가입과 첫 밭
1. 앱을 열고 「가입」을 누른다. 주소 칸에 "○○면 ○○리 123"을 입력한다. → `GET /addresses/search`
2. 결과에서 자기 주소를 고른다. 앱이 그 PNU로 필지를 불러와 지도에 보여준다. 이웃 필지도 함께 나오고, 김씨는 자기 필지 2개를 고른다. → `GET /parcels`
3. 아이디·비밀번호·밭 이름 「뒷밭」을 넣고 가입한다. 서버가 팜맵에서 필지 도형을 받아 첫 밭을 만들고 `id`를 돌려준다. 이후 모든 요청에 `X-User-Id`를 붙인다. → `POST /auth/signup`
4. 앱이 `onboarded`가 false인 것을 확인하고 온보딩 화면으로 보낸다. → `GET /me`

### B. 구역 나누기 (온보딩)
5. 작물 선택에 쓸 목록(감자·배추·토마토)을 불러온다. → `GET /crops`
6. 밭을 가로로 6:4로 나눠 미리 본다. 마음에 안 들어 3:7로 바꿔 다시 본다. 저장되지 않는다. → `POST /fields/{id}/split-preview`
7. 비율을 확정하고 A구역(배추, 정식일 9월 10일)과 B구역(감자)을 만든다. → `POST /fields/{id}/zones`
8. A구역의 과거 살포를 입력한다. 10월 1일 「엑시렐」, 10월 5일 「알칸타」. → `POST /zones/{id}/sprays` (2번)
9. 이력을 확인하고 잘못 넣은 기록 하나를 취소해 다시 입력한다. → `GET /zones/{id}/sprays`, `DELETE /zones/{id}/sprays/{sid}`
10. B구역의 정식일을 고치고 「누락 없음」을 확인한다. 정식일을 바꾸면 확인이 풀리므로 정식일을 먼저 정한다. → `PATCH /zones/{id}`
11. 모든 구역이 확인되어 온보딩을 마친다. 한 구역이라도 안 끝났으면 422다. → `POST /me/onboarding`

### C. 홈
12. 홈에서 밭별 구역과 마지막 살포·최근 판정을 본다. → `GET /fields`
13. A구역을 눌러 작용기작 편중도와 최근 판정 5건을 본다. → `GET /zones/{id}`

### D. 병해충·약제 판정
14. 배추 잎에 이상이 생겨 「병해충」 탭에서 증상 부위 「잎」을 고른다. → `GET /crops/{id}/symptom-parts`
15. 잎 증상 후보 카드의 사진을 비교해 「배추좀나방」을 고른다. → `GET /pests/candidates`
16. 이름을 알면 검색으로도 찾는다. "좀나방"을 입력한다. → `GET /pests`
17. 이 병해충에 등록된 약제 목록을 본다. 심을 때만 쓰는 약은 따로 표시된다. → `GET /pesticides`
18. 「알칸타」를 골라 판정한다. 방금 입력한 이력 때문에 ④ 작용기작 반복이 걸려 「주의」가 나오고 대안 약제가 함께 나온다. 시연용으로 `apply_date`를 넣을 수도 있다. → `POST /zones/{id}/judgments`
19. 같은 화면에서 앞으로 24시간 강수 예보를 확인하고, 비가 온다고 해서 살포를 미룬다. → `GET /zones/{id}/weather`
20. 며칠 뒤 대안 약제로 판정해 「가능」이 나오면 살포한 뒤 「살포 기록 저장」을 누른다. 네트워크가 느려 두 번 눌러도 같은 `request_id`라서 한 번만 저장된다. → `POST /zones/{id}/sprays`

### E. 조회수정
21. 「조회수정」 탭에서 이력을 다시 확인한다. → `GET /zones/{id}/sprays`
22. B구역에 감자 대신 배추를 심기로 해 작물과 정식일을 바꾼다. 새 작기가 되고 「누락 없음」이 풀린다. → `PATCH /zones/{id}`

### F. 밭 추가와 정리
23. 새 밭을 추가하려고 주소를 검색하고 필지를 고른다. 이미 쓰는 필지는 「사용 중」으로 표시된다. → `GET /addresses/search`, `GET /parcels`, `POST /fields`
24. 필지를 잘못 골랐음을 알고 방금 만든 밭을 삭제한다. → `DELETE /fields/{id}`
25. 시즌이 끝나 탈퇴한다. 모든 데이터가 지워지고 같은 `X-User-Id`는 이후 401이다. → `DELETE /me`
26. (다음 해 재방문) 로그인한다. → `POST /auth/login`

## 검수 메모

1. 주소 검색과 필지 조회는 인증이 없다. 가입 전에 써야 하기 때문이다.
2. 구역 생성에는 작물 id가 필요하므로 `GET /crops`가 그 앞에 와야 한다.
3. 정식일을 바꾸면 「누락 없음」이 풀린다. 정식일 → 이력 입력 → 마지막에 확인하는 순서를 화면에서 유도한다.
4. 날씨는 판정과 분리돼 있다. 날씨가 실패(502)해도 판정 화면은 계속 동작해야 한다.
5. 판정은 살포를 저장하지 않는다. 「살포 기록 저장」은 별도 동작이다.
