# PRD 수정 제안 (백엔드 설계 검토 결과)

- 작성일: 2026-10-11
- 대상: 루트 `PRD.md`
- 설계 문서(`docs/dev/`)는 아래 제안대로 이미 반영했다. PRD 쪽 합의가 필요하다.
- 결정 원칙: PRD P0는 고정하고 일정이 밀리면 기간을 늘린다. 프론트는 구역 분할을 균등 분할 화면까지만 감당한다.

## 1. PRD 문구·규칙을 고쳐 주세요

| # | PRD 위치 | 현재 | 제안 | 이유 |
|---|---|---|---|---|
| 1 | §4-2 1️⃣ 밭·구역 등록 | 균등 분할 + 선 긋기 직접 분할 + 경계 드래그 수정 | 균등 분할 + **비율 분할(예 6:4)** 을 P0로. 선 긋기·드래그는 P1 | 프론트가 그리기 편집을 감당하지 못한다. 비율 입력이 "경계를 옮겨 크기를 다르게"를 대신한다. 지도 배경 없이 선을 긋기도 어렵다 |
| 2 | §6 2️⃣ 결과 표시 | 내부 코드 GREEN·AMBER·RED·UNKNOWN | `OK`·`CAUTION`·`BLOCKED`·`NEEDS_CHECK` | API 계약에 한 이름만 나가야 한다. 색이 아닌 의미 이름이라 화면 색을 바꿔도 계약이 그대로다 |
| 3 | §6 3️⃣ 규칙 1 | 살포 이력 0건 → ③④ 확인 필요, 가능 표시 안 함 | **「누락 없음」 확인 전** → ③④ 확인 필요 (이력 건수 무관). 확인했고 0건이면 계산 | 원문대로면 구역의 첫 살포는 절대 "가능"이 나오지 않는다. 반대로 이력이 1건이라도 있으면 일부만 입력해도 계산돼 횟수를 적게 세는 위험이 있다. §4-2 3️⃣의 "누락 확인" 개념으로 둘 다 막는다. §4-2 3️⃣과 규칙 1이 서로 다른 말을 하는 것도 정리된다 |
| 4 | §6 3️⃣ 규칙 4·5 | 불가·주의면 대안, 대안 0개면 농업기술센터 문의 | 두 규칙 모두 "**병해충을 선택한 경우**" 단서 추가. 미선택이면 「병해충을 지정하면 대안을 볼 수 있습니다」 안내 | 대안은 같은 작물×병해충 안에서 찾는다. 미선택일 때 "문의하세요"는 병해충만 고르면 대안이 있을 수 있어 틀린 안내다 |
| 5 | §4-1, §4.3, §6 3️⃣ 규칙 6, §6 5️⃣, §7 | 데이터 기준일 | **데이터 조회일** | PSIS가 데이터 갱신일을 주지 않는다. 우리가 받아 온 날짜라 "기준일"은 사실과 다르다 |
| 6 | §6 4️⃣ | 생육단계 등 추가 조건을 확인할 수 없으면 해당 체크 확인 필요 | 수확 전 사용 기준·사용 횟수 원문을 **읽지 못한 경우**로 범위를 좁힌다. 사용 시기 원문(예 「발생초기」)은 근거로 항상 보여준다 | 사용 시기 원문은 대부분 병해충 발생 시점 안내라, 그대로 적용하면 거의 모든 판정이 확인 필요가 된다. 샘플 조사에서 정식일·생육단계 조건 비율을 세어 다시 판단한다 |
| 7 | §4-2 2️⃣ 표 셋째 줄 | 반복규칙에 필요한 정보가 부족함 → ④ 확인 필요 | 삭제 (또는 "작용기작 정보가 없는 약제 → ④ 확인 필요"로) | 정식일 표 안에 있어 정식일이 없으면 ④도 확인 필요로 읽힌다. ④는 작기와 무관하게 최근 3건을 보므로 정식일이 필요 없다 |
| 8 | §4-2 4️⃣ 촬영 | 주요 사용 방식(⭐), "포장·영수증" | P1 표시, 대상을 §5 P1과 같게 통일 | §5에서는 P1이고 "포장지"만 적혀 있다 |
| 9 | §6 3️⃣ 규칙 2 | ②③④는 각각 필요한 정보로 판단 | "병해충을 선택하지 않으면 ① 등록은 확인 필요이고, ②③은 등록된 모든 병해충 기준 중 가장 엄격한 값" 한 줄 | 규칙 2의 "각각 필요한 정보로 판단"이 무엇인지 명시 |

## 2. PRD에 없는데 넣어 주세요

| # | 항목 | 제안 |
|---|---|---|
| 1 | 로그인 | 카카오 로그인. 구역·기록이 사용자별이라 필요하다 |
| 2 | 면책 문구 | "가능"이 사용 보증으로 읽히지 않게 하는 한 줄을 품질 조건에 추가. 문구는 제품·법무가 정한다 |
| 3 | 팜맵 경계 표기 | PRD는 팜맵 경계를 「실제 경작 경계」라고 부르지만 지적도가 아니고 법적 효력이 없다. 면적·경계가 참고값이라는 표시를 품질 조건에 추가 |
| 4 | 횟수 집계 단위 | ③은 **같은 품목명** 기준으로 센다. 법령이 성분 단위라면 횟수를 적게 세어 "가능"이 잘못 나온다. 출시 전 확인 필요 항목으로 명시 |
| 5 | 구역 다시 나누기·삭제 | 재분할은 P1. 지금은 **밭 삭제**(구역·기록 포함) 후 다시 만든다. 밭 삭제를 P0 기능 목록에 추가 |
| 6 | 작물 변경 | 작물을 바꾸면 새 작기로 보고 정식일을 새로 넣거나 비운다. 기존 기록은 지우지 않는다 |
| 7 | 기록 수정 | 수정 기능은 두지 않는다. 취소 후 다시 입력 (PRD §5와 같음, 명시만) |
| 8 | 화면 구조 | 탭 4개: 홈(내 밭·구역 상태), 병해충(구역 → 병해충 → 약제 → 판정 → 기록), 조회수정(이력·구역·밭), 프로필(출처·면책 안내, 로그아웃, 회원 탈퇴) |
| 9 | 첫 사용 온보딩 | 카카오 로그인 → 밭 등록·구역 나누기 → 과거 살포 입력·「누락 없음」 확인을 마쳐야 앱을 쓸 수 있다. PRD 4-1 흐름 앞에 이 단계를 명시 |
| 10 | 회원 탈퇴 | 프로필에서 탈퇴하면 밭·구역·기록·판정을 모두 지우고 카카오 연결을 끊는다 |

## 3. 확인만 부탁드립니다

- **팜맵에 없는 밭:** 주소 없는 직접 입력(수동 구역)을 두지 않는다. 팜맵이 필지를 돌려주지 않는 밭은 등록할 수 없다. 대상 사용자에게 이런 밭이 많다면 알려 주세요.
- **정식일 라벨:** 감자는 옮겨심지 않고 씨감자를 바로 심는다. 화면 라벨을 「심은 날」로 할지.
- **매개충 자료:** 지원 작물 3종의 바이러스·매개충 연결을 원자료에서 손으로 옮긴다. 원자료(NCPMS 도감 본문, 농사로 등)와 담당.
