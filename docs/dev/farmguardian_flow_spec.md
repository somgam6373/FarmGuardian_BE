# 팜가디언 확정 흐름 · 입출력 · API 명세 (2026-10-04, 개정 2026-10-11 PRD 반영)

## 0. 확정 결정 사항

| 항목 | 결정 |
|---|---|
| 주소 검색 | 행안부 도로명주소 API (서버에서 호출) |
| 지도 | 사용 안 함. 팜맵 폴리곤과 분할 결과를 SVG로 직접 렌더링 |
| 밭·구역 | 밭 = 고른 팜맵 필지들의 합친 경계. 구역 = 밭을 방향·비율로 자른 조각 (백엔드가 계산). 균등 분할 = 비율이 모두 같음. 선 긋기·경계 드래그는 P1 |
| 작기 | ③ 횟수는 정식일 이후, 정식일이 없으면 확인 필요. ④는 작기 무관 최근 3회. 지원 작물은 감자·배추·토마토이고 모두 일년생 |
| 정식일 | 선택 항목. 구역을 먼저 만들고 나중에 넣을 수 있다 |
| 이력 확인 | 「누락 없음」 확인 전이면 ③④는 확인 필요 (이력 건수 무관) |
| 병해충 미지목 시 | ① 확인 필요. ②③은 가장 엄격한 값 (PHI=최댓값, 최대횟수=최솟값) + 안내 문구 |
| 위치 입력 | 지번/도로명 검색만. 주소 없는 직접 입력(수동 구역)은 두지 않는다 |
| 화면 구조 | 탭 4개: 홈, 병해충, 조회수정, 프로필. 첫 사용은 온보딩을 마쳐야 탭을 쓸 수 있다 |

## 1. 화면별 입력 / 출력 / API

### 온보딩 (첫 사용, 탭 없음)
`GET /me`의 `onboarded`가 false면 이 흐름으로 보낸다. 중간에 나갔다 오면 `GET /fields`로 진행 단계를 보고 이어서 한다.

| 단계 | 사용자 입력 | 시스템 출력 | 호출 |
|---|---|---|---|
| 1 가입·로그인 | 아이디·비밀번호 (가입은 2~3단계를 먼저 마친 뒤 필지 id와 밭 이름을 함께 보냄) | 사용자 id (이후 요청에 `X-User-Id`), 가입이면 첫 밭 | `POST /auth/signup`, `POST /auth/login`, `GET /me` |
| 2 주소 검색 | 지번/도로명 키워드 | 주소 후보 → 겹치는 팜맵 필지 후보 | 도로명주소 API → PNU 조립 → 팜맵 getPnuBasedFarmmapInfo |
| 3 밭 만들기 | 필지 선택(복수 가능), 밭 이름 | field (필지 경계를 합침). 첫 밭은 가입이 만들고, 추가 밭은 `POST /fields` | 팜맵 getIdBasedFarmmapInfo (폴리곤, 등록 시 1회) |
| 4 구역 나누기 | 개수·방향(·비율) → 미리보기 확인 → 구역마다 이름·작물·(선택) 정식일 | zone 여러 개 (1개면 밭 전체) | 없음 (PostGIS) |
| 5 과거 살포 입력 | 구역마다 약제+살포일(0건 가능), 「누락 없음」 확인 | spray_log (source=manual), history_confirmed | `POST /zones/{id}/sprays`, `PATCH /zones/{id}` |
| 6 완료 | - | 온보딩 완료 → 홈 | `POST /me/onboarding` (구역이 없거나 「누락 없음」 안 된 구역이 있으면 422) |

### 홈
- 내 밭: 밭별 구역과 상태 요약. 이력이 없는 구역은 「기록 없음」. 밭 추가는 온보딩 2~5단계 화면을 다시 쓴다.
- 구역 상세: 편중도 + 최근 판정 + 이력.

### 병해충 (판정)
| 단계 | 사용자 입력 | 시스템 출력 | 호출 |
|---|---|---|---|
| 1 구역 선택 | 구역 | - | DB |
| 2 병해충 지목 | 증상 부위 → 후보 / 도감 목록 / 이름 검색 / (바이러스면) 매개충 / 선택 안 함 | pest_id 또는 없음 | DB (NCPMS·PSIS 적재분, 매개충 시드) |
| 3 약제 목록 | - | 작물×병해충 등록 약제 (미지목이면 작물 등록 약제 전체) | DB (PSIS 적재분) |
| 4 약제 선택 | 약제 | 4체크 | judge() 순수 함수 |
| 5 결과 | - | 가능/주의/불가/확인 필요, 체크별 사유·근거 원문·데이터 조회일, 대안 | - |
| 6 날씨 | - | 구역 위치의 시간대별 강수 예보와 발표 시각 (실패해도 1~5는 동작) | 기상청 단기예보 (`GET /zones/{id}/weather`) |
| 7 기록 | 「살포 기록 저장」 | spray_log (기본 오늘) | `POST /zones/{id}/sprays` |

- 같은 저장의 재시도는 한 번만 반영한다 (`request_id`). 같은 구역·약제·날짜 기록이 있으면 「기존 기록 확인 / 실제 별도 살포로 저장 / 돌아가기」.

### 조회수정
- 이력 목록·취소 (취소 = 삭제), 과거 살포 추가 입력 (판정을 거치지 않음).
- 구역 수정: 이름·작물·정식일·「누락 없음」. 작물을 바꾸면 정식일을 새로 넣거나 비운다. 정식일이 바뀌면 「누락 없음」이 풀린다.
- 밭 삭제: 구역·기록 포함. 잘못 고른 필지나 다시 나누기용.

### 프로필
- 공공데이터 출처·면책 안내, 로그아웃(저장한 id만 지움), 회원 탈퇴(`DELETE /me`: 모든 데이터 삭제. 확인 화면 필수).

## 2. 주소 → PNU 변환 (도로명주소 API)

- 엔드포인트: `https://business.juso.go.kr/addrlink/addrLinkApi.do` (승인키 `confmKey`, `keyword`, `resultType=json`, `currentPage`, `countPerPage`)
- 응답에서 쓸 필드: `admCd`(10자리 법정동코드), `lnbrMnnm`(지번 본번), `lnbrSlno`(지번 부번), `mtYn`(산 여부 0/1), `jibunAddr`, `roadAddr`
- PNU(19자리) = `admCd`(10) + 필지구분(1) + 본번(4, 0 패딩) + 부번(4, 0 패딩)
  - 필지구분: mtYn=0 → `1`(대지), mtYn=1 → `2`(산)
- 호출은 반드시 서버에서 (승인키 노출 방지). 키 발급·유효기간·일일 한도는 신청 시 확인할 것.
- 농지는 도로명이 없는 경우가 많으므로 검색창에 「동/리 + 지번」 입력 안내를 표시.
- 구현 후 확인할 것: 실제 농지 지번 몇 건으로 PNU를 조립해 팜맵 `getPnuBasedFarmmapInfo`가 필지를 돌려주는지 테스트.
- 팜맵 PNU 조회는 해당 지번과 **중첩되는 팜맵 필지 전체**를 돌려준다 (기술문서 기준). 이웃 지번의 필지가 섞여 오고, 한 지번이 판독(논·밭 등)이 다른 필지 여러 개일 수 있다. 밭의 단위는 지번이 아니라 팜맵 필지(`fmapInnb`)다.

## 3. 판정 규칙 (코드로 옮길 형태)

> 세부 확정 규칙은 `farmguardian_judge_rules.md`가 우선한다. 아래와 충돌하면 그 문서를 따른다.

- 우선순위: 불가 > 확인 필요 > 주의 > 가능 (코드 `BLOCKED > NEEDS_CHECK > CAUTION > OK`)
- ① 등록 / ② 시기 / ③ 횟수 = 법·출하 문제. ④ 작용기작 = 효과 문제.
- ③ 집계 범위: zone.planted_at 이후. 정식일이 없으면 확인 필요. 작물 변경 시 정식일을 새로 받아 다시 센다.
- ③ 표시: 현재 남은 횟수 / 이번 사용 후 남을 횟수.
- ④ 집계: 구역 전체 이력의 최근 3회. 출력 예 「가1 (FRAC 4) — 최근 3회 중 2회」. 확률 표기 금지.
- 「누락 없음」 확인 전 → ③④는 확인 필요 (이력이 있어도). 확인했고 이력이 0건이면 계산한다.
- 병해충 미지목 시: ① 확인 필요. PHI=해당 작물·약제 행 중 최댓값, 최대횟수=최솟값. 화면에 「병해충을 지정하지 않아 가장 엄격한 기준을 적용했습니다」 표시.
- 결과 화면 필수 표시: 체크별 근거 원문과 데이터 조회일, 불가 약제의 사유, 불가·주의 시 다른 작용기작 대안(병해충 지목 시). 병해충을 지목했고 대안 0건일 때만 「농업기술센터 문의」.
- 문구 규칙: 예측·추천 표현 금지.
- 화면 안내 한 줄: 「횟수는 정식일 이후 기준으로 집계합니다」

## 4. 데이터 모델 변경점

- `crop.is_perennial` 없음 (지원 작물이 모두 일년생)
- `field`: 고른 팜맵 필지의 합친 경계. `field_parcel`: 필지 도형 (사용자당 한 밭에만)
- `zone`: 밭을 자른 도형, `planted_at` NULL 허용, `history_confirmed`
- `spray_log`는 zone_id만 참조, 재시도 구분용 `request_id`
- 면적: PostGIS `ST_Area(zone.geom)` (`geometry(MultiPolygon, 5179)`라 결과가 ㎡)

## 5. 남은 확인 사항

1. 도로명주소 API 승인키 신청 (가장 먼저)
2. 팜맵 갱신 주기(문서상 년 1회)와 실제 최신성 확인
3. 팜맵이 필지를 돌려주지 않는 밭 (수동 구역이 없으므로 등록 불가. S1 실호출로 확인)

닫힘 (2026-10-11): 지원 작물 = 감자·배추·토마토(모두 일년생). 복수 필지 표시 = 밭 경계 하나로 합쳐 그린다.
