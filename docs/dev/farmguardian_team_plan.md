## 1. 분담 원칙

**도메인으로 나눈다.** 두 사람이 서로 기다리지 않도록 경계를 **DB 스키마 + `judge()` 입출력 타입**으로 둔다.

- **혜빈님 = 팜맵·밭·구역 만들기 + 외부 연동 + 데이터 조사.**
  - `integrations/`: 도로명주소, PNU 조립, 팜맵 클라이언트, **팜맵 GML 파서**, **기상청 격자 변환·예보**
  - `GET /addresses/search`, `GET /parcels`, `GET /zones/{id}/weather`
  - `fields/` 전체: 밭 생성·목록·삭제, **분할 순수 함수(`split.py`)**, 분할 미리보기, 구역 생성
  - PSIS·NCPMS 샘플 데이터 조사, 팜맵 실호출 검증, 응답 예시 데이터, 면책·팜맵 안내 문구 확정, 시연용 데모 데이터
- **준혁 = 약제·판정 + 나머지.** `core`, `auth`(가입·로그인), `judge`, `records`, `ingest`(PSIS·NCPMS 적재, 문자열 파서, 매개충 시드), `pests`, `zones`(구역 상세·속성 수정), API 명세, 기획·프론트 협의.
- **DB 담당:** 개발 DB 구축, 테스트 DB 환경, DB 스키마·마이그레이션.
- 경계를 넘는 호출은 `service` 함수로만 한다. 준혁이 혜빈님에게 `zones.service.create_many`(구역 저장), `summaries`(밭 목록의 구역 요약), `centroid_wgs84`(날씨 위치)를 **S2 초반**까지 제공한다 (구역 생성이 S2이므로).
- `judge()`는 순수 함수이므로 데이터 적재 없이 fixture로 테스트한다. 두 도메인은 S2에 처음 합쳐진다.
- 폴더가 담당자 경계다 (`farmguardian_architecture.md` §4).

## 2. 가장 먼저 (S1 첫날)

- **API 키 신청:** 도로명주소 승인키, **팜맵 조회 API 활용신청** (공공데이터포털. 서버 고정 IP 등록이 필요한지 확인), **기상청 단기예보 조회서비스 활용신청** (공공데이터포털), **PSIS 키, NCPMS 키.** 발급 대기시간이 있고, PSIS 키가 늦으면 S1 샘플 조사와 계약 동결이 밀린다.

## 3. 스프린트별 계획

NCPMS 도감 적재, 매개충 데이터, 별표 8 매핑, **병해충 선택 API**(증상 부위·도감·이름 검색). e2e 테스트·문구 점검, 판정 응답시간 측정. 성분 단위 합산 규정 확인 (출시 전) | **기상청 강수 예보 API**. 시연용 데모 데이터 (배추·배추좀나방 실제 행으로 통과·반복 주의·횟수 소진·누락 확인 전·미선택 사례) |
| | 공동: 프론트 연동 버그 수정 (S3 후반은 통합 여유로 남긴다) | |

- S1~S2 동안은 고정 `X-User-Id`(데모 사용자)로 프론트가 진행할 수 있게 한다 (가입·로그인은 S3).
- S3 후반은 반드시 **통합 버그용 여유**로 남긴다. 프론트 연동에서 계약의 틈이 나온다.
- 프론트가 Setup 화면(주소 검색·필지 선택·밭 생성·구역 나누기)과 판정 화면의 실제 API를 쓰는 시점은 S2이고, 병해충·날씨·로그인은 S3이다.
- S2가 가장 무겁다 (준혁 12건, 혜빈님 7건). S1 끝에 속도를 보고 S2 일부를 S3로 넘길지 정한다.

## 4. 프론트엔드 협업 규칙

- **화면 구조:** 탭 4개 — 홈(내 밭·구역 상태), 병해충(구역 → 병해충 → 약제 → 판정 → 기록), 조회수정(이력·구역·밭), 프로필(출처·면책 안내, 로그아웃, 회원 탈퇴). 첫 사용은 가입(필지 등록으로 첫 밭 생성) → 구역 나누기 → 과거 살포 입력·「누락 없음」 확인(온보딩)을 마쳐야 탭을 쓸 수 있다. 온보딩 여부는 `GET /me`의 `onboarded`, 끝나면 `POST /me/onboarding`.
- **API 계약은 OpenAPI 파일(`openapi.json`)이 기준.** 변경은 해당 파일 PR + 프론트 승인으로만 한다.
- **스텁 먼저, 실제 구현은 나중에 교체.** FastAPI에서 `response_model`을 정의하고 fixture JSON을 반환하면 문서가 자동 생성된다. 실제 구현으로 바꿀 때 **응답 모양은 바꾸지 않는다.**
- **판정 결과 화면 필드는 S1 계약에 포함한다:** `verdict`, 체크 4개별 `message`·`facts`·`evidence`(근거 원문, 항상 있음), `notices`, `data_asof`(화면 표기는 "데이터 조회일"), `alternatives`, `show_extension_office`. ③의 「현재 남은 횟수 / 이번 사용 후」는 `facts.remaining`·`remaining_after`, ④의 비교 기록은 `facts.window`.
- **폴리곤 형식:** 팜맵 좌표(EPSG:5179)는 미터 단위 평면 좌표다. 백엔드는 **원본 좌표 + bbox만 반환**하고, 프론트가 y축을 뒤집어 SVG로 그린다. 백엔드 재투영은 하지 않는다. 밭·구역·분할 미리보기 모두 같은 형식이다.
- **필지 선택:** `GET /parcels` 응답의 `Parcel`에 `matches_query`(조회한 지번과 같은 필지인지), `land_use`(논·밭·과수·시설), `used_by_field_id`(이미 다른 밭이 쓰는 필지, 비활성 표시용)가 있다. 팜맵 PNU 조회는 이웃 지번 필지까지 돌려주고 한 지번이 여러 필지일 수 있어서 프론트가 구분해 보여줘야 한다.
- **구역 나누기:** 프론트는 개수·방향(`crosswise`/`lengthwise`, 밭의 긴 변 기준)·비율을 받아 `split-preview` 결과를 그리기만 한다. 선 긋기·드래그는 없다 (P1). 확정하면 같은 입력으로 `POST /fields/{id}/zones`.
- **살포 기록:** 「저장」 한 번에 UUID(`request_id`) 하나를 만들고 재시도에는 같은 값을 쓴다. 409 `DUPLICATE_SPRAY`면 「기존 기록 확인 / 실제 별도 살포로 저장 / 돌아가기」를 보여주고, 별도 살포면 `allow_duplicate: true`로 다시 보낸다.
- **「누락 없음」:** `PATCH /zones/{id}`의 `history_confirmed`. 온보딩의 과거 살포 입력에서 묻고, 이후에는 조회수정 탭에서 바꾼다. 정식일이 바뀌면 백엔드가 풀어 둔다.
- **날씨:** 판정과 따로 `GET /zones/{id}/weather`를 부른다. 실패하면 「날씨 조회 실패」만 표시하고 판정 화면은 그대로 둔다.
- **팜맵 면적·경계 안내:** 지적도가 아니고 법적 효력이 없는 참고값이라는 문구를 프론트와 합의한다.
- **편중도:** `rotation = {window_start | null, total, items}`. 작기 전체의 작용기작별 **건수**이고 비율은 프론트가 `count / total`로 계산한다. `window_start`가 null이면 「전체 기록 기준」.
- **프론트와 합의할 것:** 「상태 요약」의 의미, 대안·약제 목록의 묶음 방식, "가능"이 보증으로 읽히지 않게 하는 면책 문구, 분할 방향 표현, 정식일 라벨(감자는 「심은 날」 검토), 매개충 안내 고정 문구, 밭 삭제·회원 탈퇴 확인 화면.
- 스프린트 끝마다 dev 서버 데모를 프론트와 함께 한다.

## 5. 팀 운영 규칙

- 매일 10분 싱크.
- PR은 작게 (300줄 이하). **준혁이 같은 날 리뷰**하고, 리뷰 예산은 하루 1시간으로 잡는다. 리뷰가 늦으면 혜빈님이 막힌다.
- 페어 작업은 하루 1.5시간 이내로 제한한다 (`judge()`가 밀리면 제품 전체가 밀린다).
- 혜빈님 작업은 **작업 카드 + 합격 기준**을 먼저 적고, **테스트를 먼저** 쓴다. 1시간 이상 막히면 바로 질문한다.
- 계약 동결(S1 첫 주 수요일) 이후 스키마/타입 변경은 두 사람 모두 동의해야 한다.
- 입출력이 명확한 것(PNU 조립, 팜맵 GML 파서, PSIS 문자열 파서, 분할 `cut_positions`, 기상청 `latlon_to_grid`)은 순수 함수 + 표 기반 테스트로 먼저 만든다.
- 끝난 작업은 백로그 엑셀의 완료 칸을 체크한다.

## 6. 밀리면

**P0 기능은 자르지 않는다. 밀리면 기간을 늘린다** (2026-10-11 결정). 그래도 줄여야 할 때 P0 안에서 단순화하는 순서:

1. 비율 분할 → 균등 분할만. 비율 입력은 PRD의 경계 드래그를 대신하려고 넣은 것이라 PRD P0 원문에는 없다.
2. 증상 부위 후보 → 도감 목록·이름 검색만 (PRD §4-1 ③의 증상 부위 경로를 빼는 것이라 기획 동의 필요).

| 팜맵이 실제 농지 필지를 돌려주지 않음 | 수동 구역이 없어 그 밭은 등록 불가 | S1 팜맵 실호출로 조기 발견. 크면 수동 구역 재검토 (백로그에 보류로 있음) |
| 팜맵 서버 고정 IP 등록, HTTP로 키 전송 | 오류코드 32로 호출 실패, 키 노출 위험 | 키 신청 때 IP 등록 필요 여부 확인, 서버 간 호출만, 요청 URL 로그 금지 |
| 팜맵 PNU 조회가 이웃 지번 필지까지 반환 | 사용자가 엉뚱한 필지를 고름 | `matches_query`·`lnm`·`land_use`로 구분 표시, 밭 생성 전 확인 화면 (프론트). 잘못 만들면 밭 삭제 |
| NCPMS에 설명·발생시기 필드가 없음 | PRD 도감 표시 일부를 못 채움 | S1 샘플 조사로 확인. 없으면 「없음」 표시 (PRD 허용) |
| 매개충 시드를 손으로 옮김 | 잘못된 연결 | 지원 작물 3종만, 줄마다 출처 필수, 리뷰 |
| 기상청 API 장애 | 날씨 표시 실패 | 판정과 별도 호출이라 판정은 동작 (PRD 요구) |
| 프론트 연동에서 계약 틈 발견 | S3 재작업 | S1 계약에 결과 화면 필드 포함, 스프린트 데모 |
| S2 첫 통합 (`judge()` + PSIS 데이터) | 데이터 형태 불일치 | S1 PSIS 샘플 조사, fixture 공유 |
| **성분 단위 합산 규정 미확인** | 횟수를 적게 세어 "가능"이 잘못 나옴 (위험한 방향) | **출시 전 농업기술센터·PSIS 문서로 확인** (백로그 S3, 준혁) |

## 8. 미확정 사항

- 스프린트 길이(2주 가정)와 시작일
- 도로명주소·팜맵·기상청·PSIS·NCPMS 키 발급 (신청 전). 팜맵·기상청은 공공데이터포털 키이고 서버 고정 IP 등록 필요 여부와 일일 호출 한도는 신청 때 확인한다.
- 팜맵 최신성 (갱신 주기는 문서상 연 1회. 명세서 예시의 영상촬영년도가 2016이므로 실제 `vdptYr`로 확인)
- 팜맵 면적·경계 안내 문구 (지적도 아님, 법적 효력 없음)
- 별표 8 매핑표(한글 작용기작 기호 → FRAC·IRAC) 원자료와 전달 시점
- 다작용점 약제를 ④에서 제외할지 (농학 전문가 확인)
- 매개충 시드 자료의 원천
- 판정 규칙의 나머지 미결은 `farmguardian_judge_rules.md` §10
- PRD에 보낼 수정 제안 (`farmguardian_prd_feedback.md`)의 기획 합의
