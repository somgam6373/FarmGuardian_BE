## 1. 분담 원칙

**도메인으로 나눈다.** 두 사람이 서로 기다리지 않도록 경계를 **DB 스키마 + `judge()` 입출력 타입**으로 둔다.

- **팀원 = 팜맵·구역 만들기.** 팜맵과 관련된 것은 모두 팀원이 맡는다.
  - `integrations/`: 도로명주소, PNU 조립, 팜맵 클라이언트, **팜맵 GML 파서**
  - `GET /addresses/search`, `GET /parcels`
  - 구역 만들기 전체: 필지 기반 구역 생성, `POST /zones/batch`, **수동 구역**, 필지 교체(`PATCH`의 `parcel_farmmap_ids`), **사후 분할**
  - 개발환경, 스텁 API, 배포
- **팀장 = 약제·판정 + 나머지 전부.** `core`, `auth`(카카오 로그인), `judge`, `records`, `ingest`(PSIS·NCPMS 적재와 문자열 파서), `pests`, 구역 목록·상세, 구역 속성 수정(`PATCH`의 이름·작물·정식일·`no_prior_spray`).
- `zones/`는 파일로 나눈다: 쓰기(생성·batch·수동·필지 교체·분할)는 팀원, 조회와 속성 수정은 팀장. 라우터는 서로의 `service` 함수를 호출한다. 사후 분할은 팀장이 제공하는 `records.service.copy_history`를 호출한다.
- `judge()`는 순수 함수이므로 팀원의 데이터 적재 없이 fixture로 테스트한다. 두 도메인은 S2 말에 처음 합쳐진다.
- 폴더가 담당자 경계다 (`farmguardian_architecture.md` §4).

## 2. 착수 전 (S1 시작 전에 끝낼 것)

- **API 키 신청 5종:** 도로명주소 승인키, **팜맵 조회 API 활용신청** (공공데이터포털. 서버 고정 IP 등록이 필요한지 확인), 카카오 개발자 앱 등록 (Redirect URI는 프론트와 합의), **PSIS 키, NCPMS 키.** 발급 대기시간이 있고, PSIS 키가 늦으면 S1 샘플 조사와 스키마 동결이 밀린다.
- `git init` + 원격 저장소 (팀장).
- 프로젝트가 git 저장소가 아니므로 위가 끝나기 전에는 코드 협업을 시작하지 않는다.

## 3. 스프린트별 계획

| 주 | 팀장 | 팀원 |
|---|---|---|

| **S2** 핵심 완성 | `judge()` 완성 (judge_rules §4~7: 체크 4개, 우선순위, 미지목, 대안) + 판정 API 실제 구현 (스텁 교체) + `rotation_summary`. `judge()` 테스트 표(judge_rules §9)는 구현하면서 작성. **PSIS 적재** | 도로명주소 연동 + `GET /addresses/search`, 팜맵 클라이언트 + `GET /parcels` (`matches_query`·`used_by_zone_id`), 필지 저장·조회 쿼리(`ST_*`), **수동 구역** |
| **S3** API 완성 | `records` 전체 (기록·이력·수정, `copy_history`), 카카오 로그인 (`/auth/kakao`), 구역 속성 수정(`PATCH`) | **구역 생성** (필지 기반, 병렬 조회, 필지 중복 방지 409), `POST /zones/batch`, 필지 교체(`PATCH`의 `parcel_farmmap_ids`) |
| **S4** 통합 + 여유 | 구역 목록·상세, 병해충 후보 API (시드 CSV), 프론트 통합 버그 수정, e2e 테스트, 문구 점검 (예측/추천 표현 금지) | **사후 분할** (`POST /zones/{id}/split`: 필지 파티션 검증·이동, 이력 복사는 `copy_history` 호출), 통합 버그 보조, 에러 처리, 배포, 버퍼 |

- S1 동안 로그인은 스텁(고정 토큰)으로 두어 프론트가 진행할 수 있게 한다.
- S4는 반드시 **통합 버그용 여유**로 남긴다. 프론트 연동에서 계약의 틈이 나온다.
- 프론트가 Setup 화면(주소 검색·필지 선택·구역 생성)의 실제 API를 쓰는 시점은 S2~S3이고, 그 전에는 스텁을 쓴다.

## 4. 프론트엔드 협업 규칙

- **API 계약은 OpenAPI 파일(`openapi.json`)이 기준.** 변경은 해당 파일 PR + 프론트 승인으로만 한다.
- **스텁 먼저, 실제 구현은 나중에 교체.** FastAPI에서 `response_model`을 정의하고 fixture JSON을 반환하면 문서가 자동 생성된다. 실제 구현으로 바꿀 때 **응답 모양은 바꾸지 않는다.**
- **판정 결과 화면 필드는 S1 계약에 포함한다:** `verdict`, 체크 4개별 `message`·`facts`·`evidence`(근거 원문), `notices`, `data_asof`(화면 표기는 "데이터 조회일"), `alternatives`, `show_extension_office`.
- **폴리곤 형식:** 팜맵 좌표(EPSG:5179)는 미터 단위 평면 좌표다. 백엔드는 **원본 좌표 + bbox만 반환**하고, 프론트가 y축을 뒤집어 SVG로 그린다. 백엔드 재투영은 하지 않는다. 수동 구역은 폴리곤 `null` + 가로×세로(또는 면적)를 반환한다.
- **필지 선택·분할:** `GET /parcels` 응답의 `Parcel`에 `matches_query`(조회한 지번과 같은 필지인지), `land_use`(논·밭·과수·시설), `used_by_zone_id`(이미 쓰인 필지, 비활성 표시용)가 있다. 팜맵 PNU 조회는 이웃 지번 필지까지 돌려주고 한 지번이 여러 필지일 수 있어서 프론트가 구분해 보여줘야 한다. 구역 분할은 생성 시 `POST /zones/batch`, 사후는 `POST /zones/{id}/split`이고, 사후 분할 때 **이력이 모든 새 구역에 복사된다는 안내**가 필요하다.
- **팜맵 면적·경계 안내:** 지적도가 아니고 법적 효력이 없는 참고값이라는 문구를 프론트와 합의한다.
- **편중도:** `rotation = {window_start, total, items}`. 작기 전체의 작용기작별 **건수**이고 비율은 프론트가 `count / total`로 계산한다.
- **프론트와 합의할 것:** 「상태 요약」의 의미, 카카오 Redirect URI(로컬·스테이징·운영), 대안·약제 목록의 묶음 방식, "가능"이 보증으로 읽히지 않게 하는 면책 문구.
- 스프린트 끝마다 dev 서버 데모를 프론트와 함께 한다.

## 5. 팀 운영 규칙

- 매일 10분 싱크.
- PR은 작게 (300줄 이하). **팀장은 같은 날 리뷰**하고, 리뷰 예산은 하루 1시간으로 잡는다. 리뷰가 늦으면 팀원이 막힌다.
- 페어 작업은 하루 1.5시간 이내로 제한한다 (`judge()`가 밀리면 제품 전체가 밀린다).
- 팀원 작업은 **작업 카드 + 합격 기준**을 먼저 적고, **테스트를 먼저** 쓴다. 1시간 이상 막히면 바로 질문한다.
- S1 수요일 이후 스키마/타입 변경은 두 사람 모두 동의해야 한다.
- 입출력이 명확한 것(PNU 조립, 팜맵 GML 파서, PSIS 문자열 파서)은 순수 함수 + 표 기반 테스트로 먼저 만든다.

## 6. 밀리면 먼저 자를 것

1. 구역 사후 분할 (`POST /zones/{id}/split`, 팀원 S4): 생성 시 분할(`/zones/batch`)로 대체 가능하다. 필요하면 새 구역을 만들고 `PATCH`로 필지를 옮기되 이력은 따라가지 않는다.
2. `POST /zones/batch` (팀원 S3): 단일 `POST /zones`를 여러 번 호출한다 (원자성이 없어짐).
3. 병해충 후보 API: NCPMS 연동 대신 **지원 작물 시드 CSV 정적 제공** (NCPMS 적재는 MVP에서 1회 적재 + 나중에 cron)
4. 작물 변경 시 새 작기 확인 흐름
5. 수동 구역 개략 배치도 (프론트 몫이므로 백엔드는 가로×세로만 반환)

## 8. 미확정 사항

- 도로명주소·팜맵·PSIS·NCPMS 키 발급 (신청 전). 팜맵은 공공데이터포털 키이고 서버 고정 IP 등록 필요 여부와 일일 호출 한도는 신청 때 확인한다.
- 지원 작물 목록과 다년생 여부 (`is_perennial`이 ③ 집계 기준일을 바꾼다)
- 한 구역에 복수 필지 허용 시 표시 방식 (필지별 SVG로 그리는 쪽으로 가정)
- 팜맵 최신성 (갱신 주기는 문서상 연 1회. 명세서 예시의 영상촬영년도가 2016이므로 실제 `vdptYr`로 확인)
- 팜맵 면적·경계 안내 문구 (지적도 아님, 법적 효력 없음)
- 별표 8 매핑표(한글 작용기작 기호 → FRAC·IRAC) 담당과 전달 시점
- 다작용점 약제를 ④에서 제외할지 (농학 전문가 확인)
- 판정 규칙의 나머지 미결은 `farmguardian_judge_rules.md` §10
- 스프린트 시작일
