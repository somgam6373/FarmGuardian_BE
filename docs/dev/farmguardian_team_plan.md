## 1. 분담 원칙

**도메인으로 나눈다.** 두 사람이 서로 기다리지 않도록 경계를 **DB 스키마 + `judge()` 입출력 타입**으로 둔다.

- **팀원 = 팜맵·밭·구역 만들기 + 외부 연동.**
  - `integrations/`: 도로명주소, PNU 조립, 팜맵 클라이언트, **팜맵 GML 파서**, **기상청 격자 변환·예보**
  - `GET /addresses/search`, `GET /parcels`, `GET /zones/{id}/weather`
  - `fields/` 전체: 밭 생성·목록·삭제, **분할 순수 함수(`split.py`)**, 분할 미리보기, 구역 생성
  - 개발환경, 스텁 API, 배포
- **팀장 = 약제·판정 + 나머지 전부.** `core`, `auth`(카카오 로그인), `judge`, `records`, `ingest`(PSIS·NCPMS 적재, 문자열 파서, 매개충 시드), `pests`, `zones`(구역 상세·속성 수정), `seed_demo`.
- 경계를 넘는 호출은 `service` 함수로만 한다. 팀장이 팀원에게 `zones.service.create_many`(구역 저장), `summaries`(밭 목록의 구역 요약), `centroid_wgs84`(날씨 위치)를 S2 말까지 제공한다.
- `judge()`는 순수 함수이므로 팀원의 데이터 적재 없이 fixture로 테스트한다. 두 도메인은 S2 말에 처음 합쳐진다.
- 폴더가 담당자 경계다 (`farmguardian_architecture.md` §4).

## 4. 프론트엔드 협업 규칙

- **API 계약은 OpenAPI 파일(`openapi.json`)이 기준.** 변경은 해당 파일 PR + 프론트 승인으로만 한다.
- **스텁 먼저, 실제 구현은 나중에 교체.** FastAPI에서 `response_model`을 정의하고 fixture JSON을 반환하면 문서가 자동 생성된다. 실제 구현으로 바꿀 때 **응답 모양은 바꾸지 않는다.**
- **판정 결과 화면 필드는 S1 계약에 포함한다:** `verdict`, 체크 4개별 `message`·`facts`·`evidence`(근거 원문, 항상 있음), `notices`, `data_asof`(화면 표기는 "데이터 조회일"), `alternatives`, `show_extension_office`. ③의 「현재 남은 횟수 / 이번 사용 후」는 `facts.remaining`·`remaining_after`, ④의 비교 기록은 `facts.window`.
- **폴리곤 형식:** 팜맵 좌표(EPSG:5179)는 미터 단위 평면 좌표다. 백엔드는 **원본 좌표 + bbox만 반환**하고, 프론트가 y축을 뒤집어 SVG로 그린다. 백엔드 재투영은 하지 않는다. 밭·구역·분할 미리보기 모두 같은 형식이다.
- **필지 선택:** `GET /parcels` 응답의 `Parcel`에 `matches_query`(조회한 지번과 같은 필지인지), `land_use`(논·밭·과수·시설), `used_by_field_id`(이미 다른 밭이 쓰는 필지, 비활성 표시용)가 있다. 팜맵 PNU 조회는 이웃 지번 필지까지 돌려주고 한 지번이 여러 필지일 수 있어서 프론트가 구분해 보여줘야 한다.
- **구역 나누기:** 프론트는 개수·방향(`crosswise`/`lengthwise`, 밭의 긴 변 기준)·비율을 받아 `split-preview` 결과를 그리기만 한다. 선 긋기·드래그는 없다 (P1). 확정하면 같은 입력으로 `POST /fields/{id}/zones`.
- **살포 기록:** 「저장」 한 번에 UUID(`request_id`) 하나를 만들고 재시도에는 같은 값을 쓴다. 409 `DUPLICATE_SPRAY`면 「기존 기록 확인 / 실제 별도 살포로 저장 / 돌아가기」를 보여주고, 별도 살포면 `allow_duplicate: true`로 다시 보낸다.
- **「누락 없음」:** `PATCH /zones/{id}`의 `history_confirmed`. 정식일이 바뀌면 백엔드가 풀어 둔다.
- **날씨:** 판정과 따로 `GET /zones/{id}/weather`를 부른다. 실패하면 「날씨 조회 실패」만 표시하고 판정 화면은 그대로 둔다.
- **팜맵 면적·경계 안내:** 지적도가 아니고 법적 효력이 없는 참고값이라는 문구를 프론트와 합의한다.
- **편중도:** `rotation = {window_start | null, total, items}`. 작기 전체의 작용기작별 **건수**이고 비율은 프론트가 `count / total`로 계산한다. `window_start`가 null이면 「전체 기록 기준」.
- **프론트와 합의할 것:** 「상태 요약」의 의미, 카카오 Redirect URI(로컬·스테이징·운영), 대안·약제 목록의 묶음 방식, "가능"이 보증으로 읽히지 않게 하는 면책 문구, 분할 방향 표현, 「누락 없음」을 언제 묻는지, 정식일 라벨(감자는 「심은 날」 검토), 매개충 안내 고정 문구, 밭 삭제 확인 화면.
- 스프린트 끝마다 dev 서버 데모를 프론트와 함께 한다.

## 5. 팀 운영 규칙

- 매일 10분 싱크.
- PR은 작게 (300줄 이하). **팀장은 같은 날 리뷰**하고, 리뷰 예산은 하루 1시간으로 잡는다. 리뷰가 늦으면 팀원이 막힌다.
- 페어 작업은 하루 1.5시간 이내로 제한한다 (`judge()`가 밀리면 제품 전체가 밀린다).
- 팀원 작업은 **작업 카드 + 합격 기준**을 먼저 적고, **테스트를 먼저** 쓴다. 1시간 이상 막히면 바로 질문한다.
- S1 수요일 이후 스키마/타입 변경은 두 사람 모두 동의해야 한다.
- 입출력이 명확한 것(PNU 조립, 팜맵 GML 파서, PSIS 문자열 파서, 분할 `cut_positions`, 기상청 `latlon_to_grid`)은 순수 함수 + 표 기반 테스트로 먼저 만든다.

## 6. 밀리면

**P0 기능은 자르지 않는다. 밀리면 기간을 늘린다** (2026-10-11 결정). 그래도 줄여야 할 때 P0 안에서 단순화하는 순서:

1. 비율 분할 → 균등 분할만. 비율 입력은 PRD의 경계 드래그를 대신하려고 넣은 것이라 PRD P0 원문에는 없다.
2. 증상 부위 후보 → 도감 목록·이름 검색만 (PRD §4-1 ③의 증상 부위 경로를 빼는 것이라 기획 동의 필요).

| 프론트 연동에서 계약 틈 발견 | S6 재작업 | S1 계약에 결과 화면 필드 포함, 스프린트 데모 |
| S2 말 첫 통합 (`judge()` + PSIS 데이터) | 데이터 형태 불일치 | S1 PSIS 샘플 조사, fixture 공유 |
| **성분 단위 합산 규정 미확인** | 횟수를 적게 세어 "가능"이 잘못 나옴 (위험한 방향) | **출시 전 농업기술센터·PSIS 문서로 확인.** 확인 담당 지정 필요 |

## 8. 미확정 사항

- 도로명주소·팜맵·기상청·PSIS·NCPMS 키 발급 (신청 전). 팜맵·기상청은 공공데이터포털 키이고 서버 고정 IP 등록 필요 여부와 일일 호출 한도는 신청 때 확인한다.
- 팜맵 최신성 (갱신 주기는 문서상 연 1회. 명세서 예시의 영상촬영년도가 2016이므로 실제 `vdptYr`로 확인)
- 팜맵 면적·경계 안내 문구 (지적도 아님, 법적 효력 없음)
- 별표 8 매핑표(한글 작용기작 기호 → FRAC·IRAC) 담당과 전달 시점
- 다작용점 약제를 ④에서 제외할지 (농학 전문가 확인)
- 매개충 시드 자료의 원천과 담당
- 판정 규칙의 나머지 미결은 `farmguardian_judge_rules.md` §10
- PRD에 보낼 수정 제안 (`farmguardian_prd_feedback.md`)의 기획 합의
- 스프린트 시작일
